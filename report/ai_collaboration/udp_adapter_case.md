# V4 UDP接收适配：接口先于界面

## 任务和输入

提交材料检查发现：板级顶层发送40字节 `FPGA/TEC2` 状态包，旧图形程序主要按H2PK/JSON接收、默认5005。只改报告文字无法解决连接问题。

团队提供V4 RTL与V6外观程序，要求完成可交付的集成。先从 `udp_telemetry_bridge.v` 冻结端序、偏移、单位、有效位、序号和5001端口，再修改 `udp_protocol.py`、`udp_live.py` 与显示端。

## 修正

- 一个40字节报文包含状态和测频结果两个逻辑记录；真实报文计数与逻辑记录计数分开。
- 同一FFT结果序号不会因100 Hz状态重复发送而重复入图；同序号有效位变化仍立即处理。
- 无效或接收超时后撤下旧频率，不继续显示为实时结果。
- DAC和误差保留有符号原始码；缺少量程与增益时不自动转换成伏特。
- 温度m°C转°C，并保留数字模型来源及故障位。
- 40字节包不含采样数组，接收器不补造波形、FFT或PD电压。
- 标定按报告的分段线性插值；修正首个正锚点被当成零的问题。

## 执行与验收

用明确字节夹具、本机UDP套接字、序号重复/变更、有效位、超时和边界输入检查，7项新增加5项既有测试共12项通过。日志在 `../../sim/results/host_udp_tests.txt`，固定输入在 `../../src/host/gui/test_v4_integration.py`。

本轮由执行侧模型完成代码及运行检查，没有另行调用DeepSeek。此前FFT/锁频的跨模型案例保留其真实原话和独立裁决，不借用为本轮双模型验证。

## 可迁移步骤

先读发送端 → 冻结字节和单位 → 为接收器建立反例 → 最小修改 → 先跑解析与失效检查 → 最后接入界面。换成其他板卡时重写字段契约和夹具；不要直接沿用40字节格式、毫摄氏度、占空比或错误码含义。

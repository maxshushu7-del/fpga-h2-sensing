## 复审结论

**方向同意，但不算无条件通过的补丁**：这次修改确实消除了“末点成为新最小值时被误捕获”的实际缺陷，而且只改了 SWEEP_AVG 的判定表达式，FIND/反馈/接口一行都没动。但有三点必须交给执行侧确认：① 边界拒绝在候选里从“错误接受”变成“永久重试”，存在实际上的活锁；② 末点成为新最大值时只做了数值对齐、没有做对称的边界判定，并且 FIND 的接受阈值被同一改动顺带放宽了；③ FIND 阶段内部存在**同类型的非阻塞赋值陈旧问题**（不是本次引入的），候选没有改它，回归里要用小参数覆盖。

## 主要依据

**1. 是否真解决末点成为新最小值时的误捕获：解决了，而且实现方式干净。**
`auto_lock_fsm.v:52-58`（候选）把 `scan_min/scan_max/min_code/contrast/half_sum` 的“下一拍值”做成组合线，`auto_lock_fsm.v:117,121` 用这组线做判定。关键是这些组合线算出来的值，和同一时钟沿之后寄存器里实际保存的值逐位相同（`auto_lock_fsm.v:111-114,121` 用的仍是同一个比较式 `average < $signed(scan_min)`），所以判定与状态**同拍闭环、不引入额外缓冲**。旧程序 `auto_lock_fsm.v:103-113` 里，判定读的是沿前的 `contrast/min_code`，而更新在同一时刻才用非阻塞赋值提交；`min_code>=SPAN` 这条“谷底在边界就拒绝”的检查，永远看不到末点刚写进去的 `SPAN`（下一次扫描前 `min_code` 已在 `auto_lock_fsm.v:98` 被清 0），因此这条检查实际上从未生效。

具体例子（缩短参数单元测试：`SPAN=8, STEP=2, AVG_LOG2=2, MIN_CONTRAST=24`）：各码点均值 `-8:700, -6:620, -4:540, -2:460, 0:380, 2:320, 4:300, 6:300, 8:40`。旧程序在 code=8 这一拍看到 `contrast=700-300=400≥24`、`min_code=4`，于是**放行**，`half_level=(300+700)>>1=500`，随后 `min_code` 才变成 8；候选在同一拍看到 `sweep_min_code_next=8 ≥ SPAN`，于是进入 `RETRY_WAIT`、`last_reason=1`。判定已经闭合。

**2. 末点成为新最大值：数值上一致，判定上不对称（属于可接受的不对称，但有副作用）。**
`auto_lock_fsm.v:53` 与 `auto_lock_fsm.v:55-56` 让新 max 同拍进入 contrast 和半高值，与 1 的判定方式一致；没有为 max 增加边界拒绝，我认为**不需要**：当 max 落在 +SPAN 时，min 在内部，左半高点仍位于 `[-SPAN, min_code]` 内，可以被捕获；如果左端本身低于半高，FIND 的阈值会把它拒掉（`auto_lock_fsm.v:149`）。但有两点必须记录：第一，`contrast` 同时被放大，而 `contrast>>>2` 是 FIND 的接受门限，因此末点抬高 max 会让门限**变宽**；第二，半高值可能被抬高 `Δmax/2`，进而改变选码。例如：内部 max=396（contrast=96，门限 24），末点 8 的均值=400 → 新 contrast=100、门限 25；此时若 `best_diff=25`，旧程序拒绝（`last_reason=3`），候选接受。这不是缺陷，但“MIN_CONTRAST 和接受门限的实际生效值在末点这一拍发生了变化”，标定口径要按新口径记录。

**3. 符号 / 位宽 / 初始极值 / 更新时刻：没有新问题，另有一处稳健性顺带提升。**
- 符号：`auto_lock_fsm.v:52-53` 是 `average`（signed 32）对 `$signed(scan_min)`（signed 16），两者都带符号，按符号扩展后比较，与旧式一致；`>>>` 的操作数是 signed 17 位，执行的是算术右移（`auto_lock_fsm.v:121`），负半高值（例如 min=-800、max=-200 时，半高应为 -500）与旧式结果相同。
- 位宽：`contrast/half_sum` 使用 17 位有符号，**优于**旧程序 `auto_lock_fsm.v:113` 的 16 位自决定加法；但在 ADC 14 位（均值幅度 ≤8191）下，旧式永不溢出，|min+max|>32767 不可达，所以这是稳健性改进，**不是行为改变**，不必为它造回归。`average[15:0]` 截断与寄存器落值一致（均值幅度同样 ≤8191）。
- 初始极值：`scan_min=32767 / scan_max=-32768` 未改（`auto_lock_fsm.v:76`），首点仍落在 `-SPAN`，`sweep_min_code_next=-SPAN` 仍触发 `<=-SPAN` 拒绝，与旧程序等价。
- 更新时刻：寄存器更新与判定同沿、无额外一拍；FIND_AVG 读到的 `contrast/min_code` 已经是更新后的值，与判定方式统一。
- 严格 `<`：末点与既有最小值**相等**时不拒绝，`min_code` 留在内部点、半高值不变，自洽。

**4. 接口 / FIND / 反馈：确认未被误改。** 用 `Compare-Object` 对全文比对，差异只有 10 行新增 + 2 行替换（原 `contrast<...`、原 `half_level<=(...)`），净增 8 行（207→215），没有任何其他增删；端口/参数（`auto_lock_fsm.v:18-36`）、复位分支、`adc_scan_enable/servo_enable`、`reverse_error`、`servo_clear` 全部未动，FIND/LOCK/RETRY 区段文本一致。

**5. 必须提出的异议（新问题/残留）。**
- **(a) 边界拒绝→重试活锁**：当共振谷底位于 +SPAN 边缘或略超出时（例如上例的 8 处为谷底），候选每次扫描都在同一点 `last_reason=1`，`attempts` 会递增，但 SPAN 不变，系统**永远不会再锁定**；旧程序的“错误接受”至少给出了一个（偏高的）工作点。从功能上这是更安全的选择，从可用性上这是退化，需要上层确认 `last_reason=1` 的持续重试是可接受的，或者需要告警/放大 SPAN/钳位保护。
- **(b) FIND 内部同构的非阻塞赋值陈旧问题仍在**（本次未改、也未引入）：`auto_lock_fsm.v:144-149` 在最后一个 FIND 点（`scan_code==min_code`，即谷底）时，`best_diff` 的更新同样是非阻塞赋值，但接受判定读的却是沿前的值，于是末点不参与“最佳点”比较。在默认参数下，谷底不可能是半高点（`MIN_CONTRAST=24` 已经保证），所以良性；但把 `MIN_CONTRAST` 调到 0 或做极小 SPAN 的单元测试时，末点可能才是最佳匹配而被漏掉，`best_code` 会停在 `-SPAN`。这不是本次改坏，但回归要覆盖，否则以后会被误判成新补丁引入的问题。
- **(c) `STEP` 不能整除 `2*SPAN` 时末点会越过 SPAN**（例如 `SPAN=1024, STEP=3` 时末点=1025）：`>=SPAN` 判定仍能拦住，所以本次修复依旧覆盖；但 `dac_code` 会短暂输出超过 SPAN 的值。这是旧有情况，候选既未引入也未修复，只作提示。

## 可交给执行侧复现的输入序列/断言

1. **末点成为新最小值（主用例，隔离 contrast 因素）**：`SPAN=8, STEP=2, AVG_LOG2=2, SETTLE_CLOCKS=2, MIN_CONTRAST=24`；`adc_sample` 按码点给均值 `700,620,540,460,380,320,300,300,40`（每点 4 个相同采样）。断言：候选 `state==RETRY_WAIT && last_reason==1 && reacquire_count==1`；旧程序 `state==FIND_WAIT && half_level==500`。这是判定改为“同拍提交”后行为差异的直接证据。
2. **首点为最小值**：整段单调下降，末点非最小。断言：旧程序与候选都执行 `last_reason=1`（回归项，证明没有把原有的 `min_code<=-SPAN` 分支改坏）。
3. **末点成为新最大值**：均值 `-8:500, -6:440, -4:380, -2:320, 0:100, 2:320, 4:340, 6:360, 8:400`。断言：候选 `half_level==(100+400)>>1==250`（旧程序 240）；另用内部 max=396、末点=400 构造 `best_diff=25` 的门限翻转用例，记录候选从 reason=3 变成接受。
4. **活锁确认**：让 code=+SPAN 恒为全局最小，连续跑 3 次扫描；断言 `last_reason==1`×3、`attempts` 递增、永不进入 LOCKING，与设计方确认这是期望行为。
5. **FIND 末点最佳匹配（探针，用于记录残留）**：`MIN_CONTRAST=0`、极小 SPAN（如 4）、让 `|min_code 点均值 - half_level|` 最小；断言 `best_code` 是否等于 `min_code`，预期两者都停在 `-SPAN`，作为已知残留登记，不据此否决补丁。
6. **零对比度**：所有点均值相同 → `sweep_contrast_next=0 < 24`，候选 `last_reason=1`（门限改用 next 值后仍成立）。

# 定点验证工作流与可复制提问

## A. 冻结问题，而不是马上生成 RTL

将下面提示连同自己的需求、代码和契约模板交给 AI：

> 先审查这个模块的数值与接口约定，不要修改实现。列出影响结果的未知项，区分算法需求和现有 RTL 行为。明确每个量的单位、符号、位宽、小数位、乘加中间位宽、舍入/截断与饱和位置；明确何时接受输入、何时发布输出、复位如何处理在途事务。给出少量可手算的边界例子。缺失信息请标注，不沿用任何参考案例的硬件参数。

产物：填写后的 interface_contract.md。不能确认的关键项保留为阻塞项或显式假设，由需求方决定；不能把“AI认为应该这样”自动当规范。

## B. 先参考，再设计验证

> 根据已确认契约建立独立参考和测试矩阵。高精度算法参考与位准确参考分开；解释两者差异。不要逐行复制 RTL 充当参考。用手算例或独立不变量检查参考自身。测试既要覆盖数值，也要覆盖状态、输入有效间隙、复位与禁用。说明哪些检查需要逐周期断言，哪些可导出有效事务后比对。

按任务选择下列场景，不要求每个组合都适用于所有模块：

| 类别 | 候选输入/操作 | 应检查的性质 |
|---|---|---|
| 编码与符号 | 0、-1、正负极值、符号边界 | 扩展、比较、移位和输出编码一致 |
| 定点精度 | 半 LSB 附近、正负小数、长时间小增量 | 舍入/截断规则与量化偏差 |
| 饱和 | 上下限附近、一次大阶跃、持续积分 | 不回绕；满足定义的恢复行为 |
| 状态与限速 | 小误差、反向误差、达到输出限速 | 能按定义启动/退出，不因保护逻辑意外停滞 |
| 流水线 | 连续输入、空拍、参数或输入在计算中变化 | 使用哪一拍输入明确，不混合不同事务 |
| 复位/故障 | 计算途中复位、禁用、超时或故障 | 在途结果按契约取消或完成，不出现旧结果冒充新结果 |
| 边界与随机 | 可复现随机、模式交界、极限参数 | 记录种子；首个失败能缩减和重放 |

连续输出协议需明确固定延迟和顺序；乱序设计需另用允许乱序的匹配器，不能关闭顺序检查后宣称通过。跨复位若 ID 重新从零，分开记录或使用 epoch+id，不能静默去重。

## C. 用差异驱动修正

运行适配层先做最小预检：确认分析、展开、执行、输入读取和输出文件均实际完成，再跑测试矩阵。启动/参数转发错误与DUT功能差异分开记录；没有完成标记不能计入测试通过。

> 这是契约、参考依据、DUT、复现命令与首个差异。先把失败归为参考/契约问题、数值问题、事务对齐问题或状态/协议问题，并指出支持证据。若授权修改，只做有证据支持的最小修复。保留失败用例，重新运行旧回归与新反例，报告实际运行结果；未运行的项目明确标注。

原则：

- 错一拍和算错数是不同问题；不能靠移动 CSV 行掩盖丢事务或延迟变化。
- 结果暂时相同不等于未更新，用事务标识或接受/发布事件区分；数值未改变不自动是故障。
- 故障撤销、输出限幅、超时与状态恢复不能只看最终稳态值。
- 算法容差和数字实现容差分开。已知数字输入的位准确验证应尽量精确；模拟信号实验需另计参考不确定度。
- 如果新增流水级解决时序，更新接口契约和 testbench，不能只重跑综合。
- 自动化门禁同时检查测试完成标记、断言/错误计数和数值比对，而不只看宿主退出码。本轮FIR演练中，Vivado 2024.1结合`run all; quit`在Fatal后仍返回0，详见[演练记录](../validation/fir_trial.md)；不要假定其它仿真器行为相同，也不要通过降低错误级别制造PASS。

## D. CSV 工具示例

从本包 skill 目录执行，Python 3.10+，无第三方依赖：

```text
python fpga-rtl-verification/scripts/compare_vectors.py --expected fpga-rtl-verification/examples/reference.csv --actual fpga-rtl-verification/examples/observed_pass.csv --columns y
python fpga-rtl-verification/scripts/compare_vectors.py --expected fpga-rtl-verification/examples/reference.csv --actual fpga-rtl-verification/examples/observed_fail.csv --columns y
python -m unittest discover -s fpga-rtl-verification/tests -v
```

第一条应返回 PASS/退出码0；第二条故意制造一个差异，应返回 FAIL/退出码1。输入文件缺失或格式错误为 ERROR/退出码2。反例返回1不代表工具本身故障。

CSV 规则：UTF-8，首行为列名，默认唯一键 sample_id；只导出按契约已接受、已发布的事务，且样本顺序必须相同。数值列使用有限十进制，单位和缩放在契约中说明。脚本不解析二进制/十六进制，不自动解释补码、不自动过滤 valid，也不自动转换单位。

`--abs-tolerance` 默认0，非负；对本次选定的所有数值列使用同一绝对容差。不同单位或不同容差的列应分次运行。容差来自契约，不由脚本估计。工具比较数值不等于检查逐周期时序，后者仍需 testbench/断言。

三个 CSV 仅为合成的工具演示，不是某个 RTL 或跨题目验证的输出。

## 限幅测试的可观察性

边界用例除了到达极值，还应能分辨预期错误。先用参考验证相邻错误增量是否会被饱和成同一个输出，必要时选择不同初态。采用本轮±2初态的例子前，应按自己的位宽、运算和限幅重新推导，不能直接照搬常数。来源与实际修订见[本轮经验](../cases/trial_20261102.md)。

# 从本项目经历提炼方法：来源与边界

这些是技能的来源案例，不是使用者必须接手的项目。通用工作流不读取原工程盘符、寄存器地址或控制电压。案例参数只用于解释历史，不能作为新设计的默认设置。

本包不附整段私人聊天或声称“AI 已普遍掌握该能力”。下面区分真实工程记录、历史用户观察、当前工具自测和尚未完成的迁移。

## C01：保护条件正确，组合起来仍可能让控制器停滞

- 来源：`evidence/tec_report.md`，即原 `tec_control_draft_20261017/verification/report.md` 的未修改副本。
- 原观察：纯积分且有变化率限制时，原先对超出裕量的全增量拒绝可能导致控制器无法启动；后续改为接受剩余裕量允许的部分增量。
- 已有结果：源报告记载正负纯积分限速启动及饱和恢复回归；单元104项、可选项226项等是原模块仿真结果，不是通用技能测试数量。
- 提炼：测试矩阵不能只查“不超限”，还要查合法小输入下能否推进、反向后能否恢复。参考模型应体现明确契约，不能照抄现有保护逻辑而共享同一个错误。
- 可迁移任务：限速的电机/执行器控制、带状态与限幅的离散运算。但具体控制器、参数和对象稳定性需要重新验证。
- 边界：本包没有重新运行该控制器，也没有在真实执行器上验证这条迁移。

## C02：新增流水级后必须重新验证结果属于哪次输入

- 来源：同上，源报告说明抗饱和组合路径过长，拆成多个时钟阶段后重新运行功能与实现；计算期间禁用、故障和输入锁存均纳入测试。
- 提炼：数值公式不变，不代表接口行为不变。流水化会改变延迟、valid 对齐及在途取消规则；修时序时同步更新契约和协议测试。
- 可迁移任务：FIR、乘加流水线、图像统计和离散控制等。
- 边界：源模块的100MHz和20ns延迟只是当时实现，不进入通用模板。

## C03：时序数字变好，不等于板外接口已被证明

- 来源：`evidence/integration_report.md`，原联合工程验证报告的未修改副本。
- 原问题：625ps DAC转发配置下，报告中的DAC输出setup为-0.146ns；调整真实MMCM相位并保留板外约束模型后，最终候选全局setup/hold余量为+0.021/+0.010ns。
- 注意：初始的特定输出组数字与最终全局最差数字不是同一条路径的完整前后曲线；不能据此计算某条路径精确改善量。
- 提炼：看 setup 与 hold、实际时钟配置、约束依据和变更来源；不能用随意豁免路径换取表面通过。
- 已有边界：外部 I/O 模型暂定、余量小、CDC告警仍待审查，未完成实板接口验收。实际候选来自已布线检查点的相位ECO，不伪称是一次全新的完整从源构建结果。
- 可迁移任务：源同步接口、时钟调整和实现报告审查。不能把875ps直接推荐到别的板卡。

## C04：结果有效、数据新鲜与系统状态是不同维度

- 来源：同一联合报告及 `evidence/integration_results.csv`。
- 已有观察：完整数字回归有7个新结果，其中2个跳变过渡结果无效；撤销激光ARM时测频仍可有效，温度故障时测频仍继续。
- 提炼：按发布事件/序号核对新数据，按有效规则核对可信数据，按各模块状态判断系统条件；不能强求所有时刻都输出一个“有效”数字。
- 可迁移任务：采集、帧处理、模式切换和多控制模块集成。
- 边界：该CSV是原工程理想模型仿真，不是新技能在其他题目的输出，也不是实测信号。

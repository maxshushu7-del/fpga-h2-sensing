# 实现诊断报告卡片模板

## 基线与目标

- 任务/设计版本/源码与参数标识：
- 约束版本、工具完整版本、器件/速度等级：
- 综合 / 布局布线 / 检查点 ECO（实际阶段）：
- 时钟、吞吐、延迟、资源与外部接口目标：
- 复现入口与原始日志：

## 原始证据

| 检查项 | 实际结果 | 报告位置 | 依据/局限 |
|---|---|---|---|
| setup、hold 及失败端点 | 未提供则写缺失 |  | 不只报单个 WNS |
| 代表路径：起终点/时钟/逻辑与布线 |  |  | 说明为何应被检查 |
| 时钟、未约束路径与时序例外 |  |  | 0 个内部端点不代表板外模型正确 |
| LUT/寄存器/BRAM/DSP 等及模块分布 |  |  | 不直接把占比高等同瓶颈 |
| DRC/CDC/其它方法学告警 |  |  | 未解决/已审查/依据缺失分开 |
| 外部 I/O 模型来源与实测情况 |  |  | 已确认/暂定/未知 |

## 诊断与行动

- 已证实事实：
- 原因假设与支持证据：
- 尚不能排除的解释：
- 最小区分测试：
- 建议修改/本轮实际修改：
- 对数值、事务延迟、吞吐、资源、约束覆盖的影响：
- 回退点与停止条件：

## 修改后验收

- 功能与数值回归（实际运行/未运行）：
- 逐周期协议、复位与跨时钟检查：
- 同一口径的前后时序/资源结果：
- 未决告警及模型假设：
- 实物验证状态：
- 仍不能证明什么、下一项测试：

没有依据的字段不要填“正常”。数值比对通过、STA 通过、板卡工作和物理闭环稳定是不同证据。

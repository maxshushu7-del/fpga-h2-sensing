# 初稿后的迁移验证计划

状态：2026-10-18已完成第一轮中的一次作者执行FIR试用，见[实际记录](fir_trial.md)；其余仍为计划。不是赛题新增硬性要求，也不保证有固定增益。

## 验证的不是文件能否复制

要看陌生任务能否使用同一方法，并留下可核验结果。换一个工程文件夹或用已有项目改名，不算跨题目验证。

## 第一轮：与原项目不同的小型模块

| 任务 | 想验证的内容 | 提供什么 | 需要留下的结果 |
|---|---|---|---|
| 定点 FIR 或乘加流水线 | 已做一次作者执行FIR试用；独立队伍验证待做 | 新模块规格、精确参考、1358周期场景 | 正常/恢复通过，3个显式注入故障被拒绝，详见实际记录 |
| 新的流水线统计/计数模块 | 报告定位与流水化后的协议回归 | 新工程目标、约束、实际失败报告 | 原路径/约束依据、最小修改、功能/时序前后报告和未决项 |

这些任务在确定具体规格和参考之前，不能写成已预留的“保证成功”演示。故意注入的错误须标为注入；自然产生的失败另行记录。

FIR试用额外审查了OOC实现报告，但不替代第二个新统计任务上的诊断修复验证；也不是盲测或有/无技能对照。

## 第二轮：陌生使用者

请未参与编写的同学只拿本目录和自己的任务，尝试完成流程。记录需要额外解释的地方、缺少的输入、适配修改与失败。当前不把师姐协助原工程测试自动计作陌生题目试用。

## 可选的有/无技能比较

如时间允许，用同一任务、相同起始版本和可比的工具/模型条件，比较直接提问与使用工作流。记录提示词、模型/版本、尝试次数、人工提示、实际测试与耗时；明确小样本和人为因素。

没有做对照时，只报告“在某任务复用成功/失败”，不写节省多少时间或成功率提升百分比。不要求为了做对照重新制造已知失败。

## 第三轮：现场和工具适配

在本项目真实测频/PID联调中补实际接口、持续运行和失效恢复观察；它支持工程案例，但不独自证明跨题目。若换 Vivado 版本、器件或板卡，分别记录适配项与实际检查结果。

PYNQ不在本初稿已实现范围。只有确有Overlay/DMA/寄存器操作的可复用内容和测试，再作为后续独立方向，不能为了加分将现有RTL流程改称PYNQ技能。

## 每次迁移的记录表

| 字段 | 要记录什么 |
|---|---|
| 新任务/独立性 | 与来源任务的区别，是否在提炼时已经看过 |
| 输入/环境 | 原始需求、工具/模型版本、代码参数和约束 |
| 直接复用部分 | 哪些提示词、模板、脚本未修改 |
| 适配 | 修改了哪些参数/方法，为什么 |
| 结果 | 原始日志、参考、失败/修复和重跑记录 |
| 效果范围 | 合成工具自测/模块仿真/实现/现场/独立人员试用 |
| 失效条件 | 哪些情况仍无法处理，不足的信息和下一步 |

原始数据与结论一起保留，不只保留最后成功的截图。最终提交按实际证据升级状态。
